# CUMCM 2026 自主求解与论文交付计划

## Context

当前项目 `CUMCM_2026/CUMCM2026Problems` 只有 2026 年 A—E 题题面、附件和结果模板，没有可复现的求解、验证、Excel 导出或论文流水线。本计划将目标收敛为三天竞赛内自动完成一题的完整交付：读取原始附件，建立并求解全部小问，生成题目要求的结果文件、图形、验证报告、匿名 PDF 论文、AI 工具使用详情和支撑材料压缩包。

本计划固定 C 题作为主线。当前本地规范说明本科组从 A/B/C 中任选一题，高职高专组从 D/E 中任选一题；执行配置默认 `contest_group=本科`。C 题附件和五个结果模板齐全，问题之间可由同一储能优化模型逐步扩展，且供需平衡、储能边界和费用可以独立复算，适合三天内形成闭环。若实际报名组别不是本科，执行器必须停止并报告组别不匹配，不得把 C 题成果标记为可提交。

“AI 独立生成”只表示自动化研究流水线可以无人值守运行；2026 年官方 AI 工具规定仍要求核心建模与分析由参赛队主导并逐项人工审查、核实。系统最终状态固定为 `READY_FOR_HUMAN_REVIEW`，没有真实人工审查记录时不得生成虚假的合规提交状态、承诺书、签名或上传记录。

## Approach

### 1. 建立可恢复的竞赛运行状态和固定契约

在 `CUMCM_2026/autopilot/` 创建自动运行入口和配置，所有阶段只通过结构化 JSON/CSV 交换结果，不通过聊天上下文传递未经验证的数字。创建并使用：

- `CUMCM_2026/autopilot/config.yaml`：固定题号 C、默认组别本科、原始附件路径、结果模板路径、日期范围、随机种子、输出精度、求解器和论文构建参数。
- `CUMCM_2026/autopilot/requirements.txt`：固定 `numpy`、`pandas`、`scipy`、`matplotlib`、`openpyxl`、`pypdf`、`jinja2` 等实际使用依赖及版本范围；执行时优先使用 `uv` 安装，禁止临时更换未经记录的求解器。
- `CUMCM_2026/autopilot/src/contracts.py`：定义数据契约、模型契约、运行状态和验证状态；所有阶段输出必须包含 `run_id`、模型版本、输入文件校验值和求解状态。
- `CUMCM_2026/autopilot/src/provenance.py`：记录每个统计量、图表和论文数字的来源文件、计算步骤、运行编号和验证状态。
- `CUMCM_2026/autopilot/src/orchestrator.py`：实现 `INIT → DATA_AUDITED → MODEL_LOCKED → BASELINE_DONE → FULL_SOLVED → VERIFIED → PAPER_BUILT → PACKAGED → READY_FOR_HUMAN_REVIEW` 状态机；任一硬门失败则停止当前状态并回退到最近检查点。

执行器不得修改 `CUMCM_2026/CUMCM2026Problems` 下的原始附件和模板，只在 `CUMCM_2026/work/`、`CUMCM_2026/results/`、`CUMCM_2026/report/` 和 `CUMCM_2026/submission/` 写入产物。每次运行使用独立 `run_id` 目录，保留失败版本，禁止覆盖已验证版本。

### 2. 对 C 题附件和模板进行程序化审计

在 `CUMCM_2026/autopilot/src/c_data.py` 和 `CUMCM_2026/autopilot/src/audit_data.py` 中实现只读解析和规范化，输入固定为：

- `CUMCM_2026/CUMCM2026Problems/C题/附件/附件1.xlsx`：单日价格、负载、光伏预测，读取 `Sheet1` 的 144 个十分钟记录。
- `CUMCM_2026/CUMCM2026Problems/C题/附件/附件2.xlsx`：工作表 `小区负载`、`光伏发电实际功率`，读取 2025 年全年日数据。
- `CUMCM_2026/CUMCM2026Problems/C题/附件/附件3.xlsx`：四个预报时刻的未来 24 小时光伏预报。
- `CUMCM_2026/CUMCM2026Problems/C题/附件/附件4.xlsx`：全年波动电价。
- `CUMCM_2026/CUMCM2026Problems/C题/附件/附件5/`：`result1.xlsx`、`result2.xlsx`、`result3.xlsx`、`result4-2.xlsx`、`result4-3.xlsx`。

规范化规则固定如下：

1. 所有时段转换为索引 `t=0,...,143`，时间步长 `dt=1/6 h`；不依据单元格显示字符串推断顺序，而依据数据列的真实顺序和模板表头校验。
2. 功率统一保留为 kW，优化和结果输出使用电量 kWh；功率到十分钟电量统一乘以 `dt`。
3. Excel 日期序列转换为真正的 2025 日期；附件和模板中的 `0:00+1` 统一表示次日 0:00。
4. 自动检查日期连续性、每天记录数、空值、重复日期、负功率、非有限数、价格范围和附件之间的日期连接。
5. 自动读取模板工作表名称、表头、合并单元格和填充区域；导出器不得凭空重建模板，也不得改变工作表名称和题目指定的行列布局。
6. 输出 `CUMCM_2026/work/data_contract.json`、`CUMCM_2026/work/data_audit.json`、规范化 CSV 和基础趋势图。任意断言失败时不进入建模阶段。

当前已确认模板具有以下语义，执行器仍需在运行时重新读取并校验：`result1.xlsx` 包含“计划购电量”和“充放电量”；`result2.xlsx` 包含“计划购电量”“充放电量”“紧急购电量”；`result3.xlsx` 额外包含“调整购电量”；`result4-2.xlsx`、`result4-3.xlsx` 分别对应波动价格下问题 2、问题 3。模板中的日期序列和十分钟表头必须原样保留。

### 3. 固定 C 题统一储能模型

在 `CUMCM_2026/autopilot/src/c_model.py` 中使用电量变量而不是功率变量，避免 kW/kWh 混淆。对每个十分钟时段定义：

- `L_t`：负载电量，单位 kWh；
- `P_t`：光伏电量，单位 kWh；
- `G_t`：计划购电量，单位 kWh；
- `U_t`：紧急购电量，单位 kWh；
- `C_t`：电池侧充电电量，单位 kWh；
- `D_t`：电池侧放电电量，单位 kWh；
- `W_t`：弃电量，单位 kWh；
- `S_t`：储能电量，单位 kWh。

固定参数：

```text
dt = 1/6 h
S_min = 1200 kWh
S_max = 10800 kWh
P_max = 5000 kW
E_max = P_max * dt = 833.333333... kWh
eta_c = eta_d = 0.90
S_initial = 6000 kWh
```

主模型使用：

```text
G_t + U_t + P_t + D_t = L_t + C_t + W_t
S_(t+1) = S_t + eta_c*C_t - D_t/eta_d
1200 <= S_t <= 10800
0 <= C_t <= E_max
0 <= D_t <= E_max
G_t, U_t, W_t >= 0
```

“充放电效率为 90%”的主解释为充电效率和放电效率均为 90%；若把 90% 解释为往返效率，使用 `sqrt(0.90)` 的结果只作为敏感性分析，不替换主结果。弃电变量允许系统在能量过剩时弃掉光伏或计划购电，保证通过二阶段线性优化消除同时充放电的退化解：第一阶段优化题目费用，第二阶段在费用不增加超过 `1e-7` 的条件下最小化 `sum(C_t+D_t)`。只有求解器返回最优状态时，论文才可写“最优”；否则写“可行解”并记录原因。

### 4. 按题目小问逐步扩展模型

在 `CUMCM_2026/autopilot/src/c_questions.py` 中实现四个独立入口，所有入口复用 `c_model.py` 的状态方程和 `c_settlement.py` 的费用计算。

#### 问题 1

使用附件 1 的单日价格、负载和光伏预测，令 `S_0=6000`、`S_144=6000`，目标为最小化全天计划购电费用 `sum(price_t*G_t)`，不设置紧急购电。结果写入 `result1.xlsx`，包括 144 个计划购电量和模板要求的分时段充放电量、0:00 与 24:00 储能量。

#### 问题 2

计划必须在每天 0:00 形成，不能使用当天未来实际负载和实际光伏作为决策输入。实现 `CUMCM_2026/autopilot/src/c_forecast.py`，用截至前一日的数据进行滚动起点验证，在以下固定候选中选择验证期综合损失最低者：前一日同一时段、前四周同星期同一时段中位数、带星期/时段 Fourier 特征的岭回归。综合损失为归一化负载 MAE、归一化光伏 MAE 与五倍光伏低估损失之和；未来日期不得进入训练窗口。

从 2025 年 1 月 1 日初始储能 6000 kWh 开始执行同一策略，将 1 月作为状态预热，输出范围为 2025 年 2 月 1 日至 12 月 31 日。每天 0:00 生成计划购电，实际负载和光伏到达后使用储能进行再调度，供电不足部分记为 `U_t`，紧急购电价格为普通购电价格的 5 倍。使用每日滚动 48 小时优化、只执行前 24 小时的计划，以避免 24 小时末端储能的人工边界；第二天状态使用前一天实际执行后的 `S`。题目未要求每天储能循环，禁止在主模型中强加逐日 `S_144=S_0`；问题 1 的日循环约束仅限问题 1。结果写入 `result2.xlsx`。

#### 问题 3

0:00 的计划使用附件 3 当日 0:00 预报；6:00、12:00、18:00 到达新预报后，只对尚未执行的时段重新优化。固定保留初始计划 `G^0`，在最终调整计划 `G^F` 下计算：

```text
r_minus_t = max(G^0_t - G^F_t, 0)
r_plus_t  = max(G^F_t - G^0_t, 0)
```

结算费用采用题面给出的计划费用、下调违约费用、上调超额费用和紧急购电费用：

```text
sum(price_t*G^0_t
    + 0.5*price_t*r_minus_t
    + 1.5*price_t*r_plus_t
    + 5*price_t*U_t)
```

“调整购电量”工作表填入相对初始计划的有符号调整量，正数表示增加、负数表示减少；论文和验证报告明确说明符号含义。输出最终实际充放电、紧急购电和初始计划/最终调整计划，写入 `result3.xlsx`。同时运行“只使用 0:00 预报”和“使用四次预报”的同口径回测，回答是否需要后续预报。

#### 问题 4

问题 4-2 和问题 4-3 使用附件 4 的全年波动价格作为实际结算价格，分别复用问题 2、问题 3 的控制逻辑。计划阶段的价格预测只能使用历史价格：候选为前一日同一时段、前四周同星期同一时段中位数和指数平滑，按历史滚动回测选择。实际价格只在费用复算阶段使用，不得泄露到计划决策。结果分别写入 `result4-2.xlsx` 和 `result4-3.xlsx`，并保存价格预测误差、实际费用、紧急购电量和调整量的比较表。

### 5. 运行候选模型、实验和自动选择规则

在 `CUMCM_2026/autopilot/src/experiments.py` 中对预测器和储能边界策略做滚动起点回测。实验必须区分训练期、验证期和最终输出期，最终输出日期不得参与模型选择。

固定模型选择顺序：

1. 先淘汰不能覆盖全部小问、不能生成模板文件、约束不满足或求解状态失败的版本；
2. 在剩余版本中最小化实际费用、紧急购电惩罚和预测低估惩罚组成的验证损失；
3. 损失差小于 0.1% 时优先选择变量少、运行快、解释清楚的版本；
4. 所有候选都失败时回退到已验证的线性规划基础模型，并在运行日志中记录回退原因。

每个候选版本放在独立 `run_id` 目录，记录配置、输入校验值、求解器版本、目标函数、求解时间和随机种子。不得让一个 AI 代理同时生成求解器和最终验证结论；验证器只能读取模型契约、原始输入和结果文件。

### 6. 独立验证和反例测试

在 `CUMCM_2026/autopilot/src/verify_c.py`、`verify_templates.py` 和 `toy_cases.py` 中实现不依赖求解器内部变量的验证。

必须通过以下硬门：

- 每个时间点重新计算供需平衡，最大绝对误差不超过 `1e-6 kWh`；
- 所有储能量均在 `[1200,10800]`；
- 充放电量不超过 `833.333333... kWh`；
- 购电、紧急购电和弃电量均非负；
- 问题 1 的起止储能量都为 6000 kWh；
- 问题 2—4 的跨日状态和实际执行状态连续；
- 紧急购电仅在计划供给、光伏和可用储能无法满足负载时出现；
- 独立费用复算与结果元数据一致；
- 预测训练窗口不包含目标日期之后的数据；
- 结果模板的工作表、表头、日期范围、非空区域和数值精度均正确；
- 二阶段优化后没有 `C_t>0` 且 `D_t>0` 的时段，或有明确的退化证明和报告。

`toy_cases.py` 使用少量时段对模型做穷举验证，至少覆盖无光伏、光伏过剩、储能上下限、紧急购电和充放电功率受限五种情况。还要做性质测试：扩大储能容量不能增加最优成本；删除约束不能使最优目标恶化；光伏全部设为 0 时模型退化为无光伏情形；把价格整体放大时费用按同倍数变化。

所有验证产物写入 `CUMCM_2026/validation/<run_id>/`，生成 `validation_report.json` 和 `validation_report.html`。任何一个硬门失败，编排器不得进入论文生成阶段。

### 7. 模板化生成结果文件和图表

在 `CUMCM_2026/autopilot/src/export_c.py` 中复制对应原始模板到 `CUMCM_2026/results/<run_id>/` 后填值，保留工作表、样式、合并单元格和表头。不得通过重新创建空白工作簿替代模板。

必须生成：

```text
CUMCM_2026/results/<run_id>/result1.xlsx
CUMCM_2026/results/<run_id>/result2.xlsx
CUMCM_2026/results/<run_id>/result3.xlsx
CUMCM_2026/results/<run_id>/result4-2.xlsx
CUMCM_2026/results/<run_id>/result4-3.xlsx
```

在 `CUMCM_2026/report/figures/<run_id>/` 生成论文所需图形：典型日负载/光伏/价格曲线、储能状态曲线、计划购电和紧急购电对比、预测更新对比、波动价格成本对比和敏感性分析图。图形只读取已验证的 CSV/JSON，不直接读取求解器内存对象。

### 8. 自动生成匿名论文和 AI 使用详情

在 `CUMCM_2026/report/` 创建：

- `claims.json`：所有允许进入论文的经过验证的事实及其来源；
- `build_paper.py`：从 claims、公式、表格和图形生成 TeX；
- `paper.tex`：论文主文件；
- `ai_usage.tex`：AI 工具使用详情 PDF 的源文件；
- `code_listing.tex`：自动引用完整可运行源程序；
- `references.bib`：只收录实际使用且可核验的资料。

论文结构固定为：摘要、问题重述、符号说明、数据处理、问题 1—4 模型、算法与求解、结果分析、敏感性分析、模型评价、结论、AI 工具使用声明、参考文献、附录。电子论文不放承诺书和编号专用页，摘要页作为电子论文第一页，摘要原则上控制为一页，正文不超过 30 页，不放目录，不出现参赛队、学校、赛区和队员身份。

在参考文献之前插入官方要求的使用分支声明，并根据实际记录填充用途：

```text
本参赛队在竞赛过程中使用了AI工具，主要用于题意整理、代码生成与调试、数值校验和语言润色，详细使用情况见支撑材料。
```

`ai_usage.tex` 必须从实际 `CUMCM_2026/work/ai_trace.jsonl` 生成 `AI工具使用详情.pdf`，包括实际使用的工具名称、版本或型号、每个环节的目的、典型提示方式、AI 输出的采纳、人工修改和核验情况。没有实际记录的工具、交互和人工审查不得补写。

论文中的每个数值、表格结论和“优于基准”的表述都必须来自 `claims.json` 且 `verified=true`。论文生成后用 `pypdf` 检查页数和文本，用 XeLaTeX 重新构建，避免公式、中文字体、图表和交叉引用只通过源代码检查。

### 9. 生成支撑材料并设置合规闸门

在 `CUMCM_2026/autopilot/src/package_submission.py` 中生成：

```text
CUMCM_2026/submission/paper.pdf
CUMCM_2026/submission/support_materials.zip
CUMCM_2026/submission/AI工具使用详情.pdf
CUMCM_2026/submission/manifest.json
CUMCM_2026/submission/validation_report.json
CUMCM_2026/submission/human_review_checklist.json
```

支撑材料 ZIP 包含：完整可运行源程序、实际使用的外部资料、全部结果 Excel、图形、中间结果、模型契约、运行配置、验证报告、AI 工具使用详情 PDF 和文件清单；不重复打包赛题原始附件，不包含 `.git`、`.DS_Store`、绝对路径、账号、密码、API 密钥和队伍身份信息。使用 Python `zipfile` 生成标准 ZIP，检查 ZIP 可读性和大小；若赛区另行要求 WinRAR，由最终人工提交者按赛区要求重新压缩，不由系统伪造工具来源。

自动检查：论文 PDF 为单文件且小于 20 MB；支撑材料为单个 ZIP 且小于 20 MB；附录文件清单与 ZIP 成员完全一致；论文、结果 Excel、验证报告和代码来自同一 `run_id`。`human_review_checklist.json` 初始为未审查状态，系统不得将其改为已审查。

### 10. 三天自动执行节奏和硬性阶段闸门

第一天执行：读取规范和题面、审计 C 题附件与模板、生成数据契约、跑通单日问题 1、完成问题 2—4 的基础接口和 toy case。闸门是：数据断言通过、统一模型可解、至少一个结果模板可以正确写回。

第二天执行：完成因果预测回测、全年问题 2—4 求解、波动价格版本、所有结果文件和独立验证。闸门是：全部小问均有结果、求解状态合格、约束和费用复算通过、结果文件可重新打开。

第三天执行：运行敏感性分析、锁定主模型、生成论文图表和 PDF、生成 AI 工具使用详情、压缩支撑材料、完成逐页和逐文件审计。闸门是：论文与结果文件数字一致、正文页数和匿名性合格、ZIP 与附录清单一致、最终状态仅为 `READY_FOR_HUMAN_REVIEW`。

运行入口固定为：

```text
cd CUMCM_2026
uv run python -m autopilot.run_pipeline --config autopilot/config.yaml
uv run python -m autopilot.verify --run-id <run_id>
uv run python -m autopilot.build_report --run-id <run_id>
uv run python -m autopilot.package_submission --run-id <run_id>
```

若 `uv` 无法安装依赖，执行器先尝试使用已安装环境；仍缺少 Excel 读写库时停止并输出缺失依赖，不生成伪造结果。若求解器超时，按记录的回退顺序使用线性规划基础模型，不临时修改论文结论。

- `CUMCM_2026/CUMCM2026Problems/C题/C题.pdf`：四个问题的原始约束、附件含义、结果文件语义和储能参数。

## Verification

执行端到端命令后，必须观察到 `run_pipeline` 为同一 `run_id` 生成五个结果 Excel、验证 JSON、论文 PDF、AI 工具使用详情 PDF 和支撑材料 ZIP；任一缺失都视为失败。

验证器重新读取原始输入和结果文件，不调用求解器内存变量，输出以下可观察结果：供需平衡最大误差不超过 `1e-6 kWh`；储能量、充放电量、购电量和日期范围全部通过边界检查；独立复算费用与运行记录一致；所有模板工作表和表头一致；预测训练窗口没有未来数据；小规模 toy case 与穷举结果一致。

论文验证器使用 XeLaTeX 构建 `paper.pdf`，使用 `pypdf` 检查电子论文第一页为摘要、参考文献前存在 AI 工具使用声明、正文不超过 30 页、文本中不存在队伍身份字段；使用 `zipfile.testzip()` 检查支撑材料；使用 Excel 读取器重新打开每个结果文件并检查无空值、无 `NaN`、无 `Inf`。最后比较 `claims.json`、论文表格、结果 Excel 和验证报告中的所有关键数字，数字不一致则阻止打包。

合规验证使用官方 AI 工具规定页面作为执行期依据：`https://www.mcm.edu.cn/html_cn/node/fef94648f2836ab6cc81586f4c38512b.html`。系统必须生成真实 AI 使用详情，但不得代替参赛队对核心模型、分析和最终作品进行逐项人工审查；没有人工审查记录时，最终报告明确显示“自动化研究成果，待人工审查”，不得上传或提交。

## Assumptions & contingencies

- 默认参赛组别为本科，故固定 C 题；若运行配置明确为高职高专，执行器停止而不擅自把 C 题改成 D/E。
- 主模型将 90% 解释为充电效率和放电效率各为 90%；往返效率解释仅做敏感性分析并在论文中标注。
- 问题 1 使用题面明确的 0:00—24:00 储能相等约束；问题 2—4 不强加逐日循环，采用滚动 48 小时、只执行首日的因果策略，跨日储能状态连续。
- 问题 2—4 的计划输入不能读取目标日未来实际值；附件中的实际负载、实际光伏和实际价格只用于回测、执行模拟和费用复算。
- 问题 3 的调整量采用相对初始计划的有符号值，并在正文中定义正负号；若模板只接受非负量，导出器必须同时写入题目要求的数量列和支撑材料中的有符号内部列，不能静默丢失方向信息。
- 论文和 AI 使用详情只能陈述实际发生并被验证的运行；缺失模型版本、工具版本或人工核验信息时写“待补录并阻止合规提交”，不猜测、不补造。
- 官方规则要求核心建模和分析由参赛队主导并人工核验；多模型投票、自动验证和 AI 互审只能提高内部可靠性，不能被写成“替代人工审查”。
