联合调度候选说明

API
choose_task(position, anchors, targets, *, choice="guarded") -> (kind, index)。anchors 是 index->(x,y)，targets 是 channel->((x,y), radius)。返回值仅表示下一项；Main 在线执行后必须依据新的公开观测重建两个映射。choice="center" 只用中心点；choice="guarded" 对首项增加该目标的 MEC 半径，锚点半径视为 0。两种模式都保留每一个锚点和目标，空集或非法 choice 抛 ValueError；几何/半径非有限时也拒绝。

代理目标
候选先用固定当前位置作起点的最近插入构造包含全部任务的开放路线，再做至多 n 轮、字典序扫描的严格改进 2-opt，返回路线首项。center 模式近似最小化“当前位置到首项加相邻任务间欧氏距离”的开放路线长度。guarded 模式在这个代理上再加首项 MEC 半径，代表在不确定中心上立刻作出长距离承诺的风险；这不是对未来真实路径的估计。半径只加入首项，因此不会把不确定任务永久删除或伪装成已完成。

证明与安全性
任务排列在构造、插入和反转中始终包含全部输入项，故算法只重排任务，不可能删掉全清证书所需的骨架扫描。2-opt 只反转连续排列区间，开放路线不增加回到起点的虚拟边。tie 顺序固定为 target 后按输入键排序、再 anchor 按键排序；插入空隙和 2-opt 均左到右，且只接受严格改善。因此相同输入可复现，函数不修改两个映射。模块无 I/O、随机数和外部依赖。

局限
真实 T 还包含扫描耗时、测向次数、失败恢复、局部化路径、超时和目标在 MEC 内的实际位置；几何中心距离或半径惩罚都不等价于 T，也不构成目标位置安全界。guarded 的半径不是“必须绕开”的障碍，不能证明实际移动不绕路；center 可能先追逐一个后来被测向修正的中心。2-opt 有 n 轮上限，只保证代理目标的确定性改进，不保证局部最优或全局最优。Main 必须保留既有局部化、光学后备和全清证书逻辑，不能在代理点直接 clear。

Main 可解析场景（仅供运行时筛选，本文未运行验证）
1. 空任务：choose_task((0,0), {}, {}) 应抛 ValueError。
2. 不确定目标与锚点：position=(0,0)，targets={3:((1,0),20)}，anchors={7:(-2,0),9:(10,0)}。可分别运行 choice="center" 与 "guarded"，记录首项和公开动作后的虚拟时间；这是检验风险惩罚是否改变顺序的有限场景，不是收益声明。
3. 半径为 0 的目标：同一 anchors/targets 以 radius=0 分别运行两种 choice，结果应与仅按中心代理的决策一致。
4. 重合任务：两个不同 ID 使用同一点，检查返回一种任务后 Main 重建映射仍可返回另一种，不能按坐标去重。

复杂度
n 为 anchors 与 targets 总数；距离矩阵 O(n²) 存储，最近插入 O(n²)，至多 n 轮扫描 2-opt 为 O(n³) 时间。所有边界判定和证书更新仍由 Main 负责。
